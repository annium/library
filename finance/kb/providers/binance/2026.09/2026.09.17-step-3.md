## The discrepancy, and what turned up behind it

**The manifest's claim** (§3): "`pinned` per converter, every one having its own test with real fixtures".
Literally true and misleading in meaning: a converter has a test, and a branch inside it may never have
been executed.

**The uncovered branch.** `UsdFutures/.../OrderUpdateEventConverter.cs:83` synthesises `createdAt`:
`status is OrderStatus.New ? transactionTime : 0L`. The only populated fixture carried
`"X": "PARTIALLY_FILLED"`, so only the `else 0` side ever ran. Collapsing the ternary either way would
have gone unnoticed.

Closed: `Works` became a `Theory` covering both statuses. Both mutants die — "always 0" fails the `NEW`
case, "always transactionTime" fails `PARTIALLY_FILLED`.

Alongside it: spot synthesises nothing, its event carries `O`, and it pins that value with a real number.
The asymmetry is legitimate — the futures `ORDER_TRADE_UPDATE` does not carry the order's creation time —
and the manifest records it. It now also records that both halves are pinned.

## A defect found by a negative-branch test

An attempt to pin the rule "an asset with no margin is dropped" **failed** — the asset was not dropped.

The cause was not `AssetConverter`, which honestly returns `null`, but the envelope:

```csharp
// before
assets = JsonSerializer.Deserialize<IReadOnlyCollection<Asset>?>(ref reader, options);
```

The array was read into a collection whose **element type was not nullable**, and the returned `null`
stayed in it. The drop rule was written and thrown away one line below. The neighbouring `symbols` in the
same converter does it correctly — reads `InstrumentModel?` and filters through `OfType` — so the
discrepancy lived inside one file, between two adjacent `switch` branches.

**The cost.** `MarketProvider.LoadContextAsync` walks that collection first and reads `asset.Code` on
every entry. A `null` there is a `NullReferenceException` on the context load path, which is to say at
connector startup, depending on what the exchange puts in `assets`.

Fixed after the neighbouring branch's pattern; the "keep the `null`" mutant dies.
